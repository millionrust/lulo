# Idle CPU repair — 2026-09-29

The reference laptop ran the installed `rmac-apps 0.9.0~beta.1-38` release
build for the before sample. Each app had one open window, a private HOME and
XDG config/data/state/cache tree, a three-second settle, and a 60-second
idle interval in the live niri session. The runner did not inject input.
The [raw live report](idle-cpu-2026-09-29/before-live.json) includes CPU and
context-switch rates. Context switches are a wake-up proxy, not exact timer or
frame counts. The [private Sway samples](idle-cpu-2026-09-29/before-private/)
are separate diagnostics: software rendering makes their CPU percentages
incomparable with the live desktop.

The after sample used the five `cargo build --release` binaries from this
branch, on the same laptop and with the same live runner settings. The
[candidate report](idle-cpu-2026-09-29/after-live.json) records the values;
[SHA-256 hashes](idle-cpu-2026-09-29/release-binaries.sha256) identify the
measured binaries. The candidate has not been installed as a package.

Files already passes in the installed build. Its source uses the Linux native
`notify` watcher, filters access notifications, and waits on `/proc/self/mounts`
`POLLPRI` for mount changes. It has no directory scan timer. The earlier
release report traced its old access-event reload loop; the current source
contains that fix.

Clock's visible second hand drove a full-window repaint each second. World
Clock now displays minute-resolution hands and waits for the next minute
boundary. Static tabs wait on native file events from the saved state; inactive
windows cancel their redraw timer. A running stopwatch or countdown retains
the precision it displays. The hidden second hand is recorded as CLOCK-10 in
`docs/parity.md`.

System Monitor previously refreshed the full process table every two seconds.
It now samples every five seconds while its window is active and takes a fresh
sample on activation. Network and disk rates use the actual elapsed time after
reactivation. GPUI exposes window activation but not compositor
occlusion; an inactive yet partly visible monitor therefore pauses too.

Text Editor's focused input caret triggered two repaints per second. The
shared input component now parks the caret visibly after two seconds without
editing and cancels the blink task immediately when the window deactivates.
Focus and typing remain intact. Weather's empty profile previously focused
Search and inherited the same blink cost; it now starts with the main window
focused, starts no timers until a city is added, and refreshes forecasts
automatically no more than hourly.

The shell was sampled concurrently across all running units for 60 seconds:
**0.167% CPU before and 0.200% after**, below its 0.5% budget, with
**2.150 and 1.300 context switches/s** respectively. The
[before](idle-cpu-2026-09-29/shell-before.json) and
[after](idle-cpu-2026-09-29/shell-after.json) reports break out top bar,
Dock, wallpaper, notification center, and the other units. No shell code
change was needed for the CPU budget.
An eight-second read-only `strace` of the Focus service saw five completed
`recvmsg` calls and one `timerfd_settime` call; it did not show a repeated
directory scan or redraw loop. The nonzero context-switch rate must not be
read as a count of rendered frames.

The five app package test suites passed **407 tests**; the vendored input
component, assets, and macros passed **297 tests**. Clippy passed for all
eight packages with `-D warnings`. The [nested Text Editor check](idle-cpu-2026-09-29/text-editor-find.json)
passed 1/1 after a four-second idle pause and then typing into Find. The
performance script's focused Python tests passed 66/66. A final Clock-only
rerun after removing the polling fallback passed 57/57 tests, root formatting,
and Clippy with `-D warnings`.

GPUI exposes activation but no compositor occlusion state. Clock and System
Monitor therefore stop their timers on deactivation; an active window fully
covered without losing activation cannot be distinguished from a visible
one by these views. System Monitor's remaining 1.367 context switches/s
occur while its visible metrics are sampled every five seconds. Clock's
0.267/s includes its minute-boundary update. The proxy does not prove that
every remaining context switch rendered a frame.
